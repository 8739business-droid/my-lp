# 業種別プロンプト集 スキーマ v1

## ファイル構造

```jsonc
{
  "id": "food",                     // food / realestate / recruit / construction
  "label": "飲食",
  "lede": "この業種で何を作ることになるか、どこで費用と信用が決まるかを3〜5文",
  "subcategories": [                 // 5〜7個。prompts の sub はこの id のみ使用可
    { "id": "dish", "label": "料理・ドリンク" }
  ],
  "prompts": [ Prompt, ... 30件ちょうど ]
}
```

## Prompt

```jsonc
{
  "id": "food-01",                  // <pack>-01 から連番
  "sub": "dish",
  "title": "プロンプト名（12〜24字、何を作るものか一読でわかる）",
  "purpose": "何のために使うか。誰に何を伝える素材か。1〜2文",
  "model": "推奨ツール。下の「ツールの書き方」に従う",
  "text": "English prompt body.",   // DOC の場合のみ日本語の雛形でよい
  "effect": "期待する効果。なぜその指定で狙いが出るのかを物理・構造で1〜3文",
  "caution": "実務上の注意。破綻しやすい点、避けるべき表現、確認すべきこと。1〜3文",
  "status": "未検証",               // 必ずこの値
  "flow": {
    "code": "T2I",                  // T2I / I2I / I2V / T2V / V2V / SLOT / DOC
    "step": "工程1 / 2",            // 単発なら "単発"
    "input": "何を入力するか。40〜90字。新規なのか既存素材を使うのかを必ず明示",
    "output": "何が出てくるか。30〜70字",
    "next": "この出力を次に何に使うか。30〜80字。無ければ「ここで完結」"
  }
}
```

### flow の code（この7種類以外は使わない）

| code | 意味 |
|---|---|
| `T2I` | テキストから新しく**静止画**を作る |
| `I2I` | 既存の画像を**参照として渡し**、新しい静止画を作る |
| `I2V` | **すでにある静止画を動かして動画にする**。画像は新しく作らない |
| `T2V` | 画像を経由せず、テキストから直接**動画**を作る |
| `V2V` | **既存の動画を入力**にして、変種や部分修正を作る |
| `SLOT` | 単体では使わない**プロンプトの部品**。他のプロンプトの該当スロットに差し込む |
| `DOC` | 生成AIに投げるものではない**文書・表の雛形** |

### 30本の内訳（この配分を守る）

- `T2I` 10〜12本
- `I2V` 8〜10本（うち半分は、同じパック内の T2I プロンプトの出力を受け取る「工程2 / 2」にする）
- `I2I` 3〜4本
- `T2V` 1〜2本
- `V2V` 2〜3本
- `SLOT` 2〜3本
- `DOC` 1〜2本

**T2I と I2V は必ずペアで設計すること。** T2I 側の `next` で I2V 側の `title` を名指しし、I2V 側の `input` で「◯◯（T2I）で作った静止画1枚。新しく画像は作らない」と書く。これが本教材の最重要の分かりやすさの仕掛けです。

## ツールの書き方（重要・方針が変わりました）

**静止画はツールを選びません。** 学習者は ChatGPT と Gemini を契約済みで、Higgsfield 以外で画像を作って持ち込む方針です。**Higgsfield の価値は、その画像を動画にするところにあります。**

- `T2I` / `I2I` の `model` は次の形で書く：
  `"静止画。手持ちのツールで可（ChatGPT / Gemini / Higgsfield の Soul 2.0 など）。文字を正確に出したい場合は後述の注意を参照"`
  用途によって向き不向きがある場合だけ、その理由を添えて具体名を挙げる。
- `I2V` / `T2V` / `V2V` の `model` は Higgsfield のモデルを指定する。確認済みの単価（1クレジット＝$0.05）：
  - **Wan 2.7**　5秒720p = 8クレジット。流体・液体・湯気・重力表現に強い。最安
  - **Kling 3.0**　5秒720p = 10、**5秒1080p = 12.5**。カメラ移動が安定。1080pでも安く、b-roll の主力
  - **Seedance 2.0 Fast**　8秒720p = 28。下書き・大量試行用
  - **Seedance 2.0**　8秒720p = 36、5秒1080p = 45。標準。4Kも可
  - **Seedance 2.5**　8秒720p = 52、8秒1080p = 72。人物の動きと表情の質が要る最終カットのみ。**Unlimited 対象外で最も高い**
  - Soul 2.0・Seedance 2.0 系・Kling 3.0・Wan 2.7 は **Unlimited 対象**。Seedance 2.5 と Studio 系（Marketing Studio、Ads Studio、Ad Multiplier）は**対象外で常に課金**
  - `model` には「尺・解像度・想定クレジット」まで書くこと。例：`"Higgsfield / Kling 3.0、5秒・1080p（約12.5クレジット）"`

## プロンプト本文（text）の書き方

英語。次の7要素が識別できる構造にする（ラベルは付けず、この順で連結する）。

被写体 → 動作 → 環境 → カメラ（ショットサイズ・アングル・焦点距離・被写界深度）→ 光（方向・質・色温度）→ 質感 → スタイル

- `I2V` の本文は**動きの記述だけ**にする。構図・光・色は静止画で確定済みなので触れない。カメラの動きは**1カットにつき1種類**。`slow` `subtle` `constant speed` `no cuts` を添えて破綻率を下げる。
- 抽象的な形容詞（beautiful, amazing, professional, high quality）を使わない。**観測可能な物理条件**に置き換える。「高級感」→ 低いキー、深い影、暗い背景、研磨面のハイライト。
- **文字とロゴは生成させない。** 看板・値札・パッケージの文字は高確率で崩れる。構図で小さく写すかボケに置き、実物は編集工程で合成する。本文に `no text, no logo` を入れる。
- 可変部分は `[ ]` で囲む（例：`[dish name]`、`[property type]`）。

## 執筆の前提

- 読者は飲食店運営10年以上、広告運用の実績があり、北海道ニセコ・倶知安周辺の事業者を顧客にする制作者。**この人が顧客に売るための素材**を作るプロンプト集です。
- 日本の市場・季節・商習慣に合わせる。インバウンド需要の高い地域であることを織り込む。
- 「必ず成果が出る」といった断定をしない。
- 実在の施設・人物・商品を扱う場合の確認事項を `caution` に書く。**ただし法令の細かい解釈は書かない**（パック全体の法的注意は別途こちらで用意します）。「実物と異なる表現は景品表示法上の問題になりうるため、必ず依頼主に確認する」程度に留める。
